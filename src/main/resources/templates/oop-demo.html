Concept 1
Encapsulation

Hiding internal object state via strictly private variables and exposing validated public accessors/mutators (getters & setters).

  • Validated capacity: rejects values ≤ 0 or > 100
  • Email regex invariant validation
  • Contact privacy masking (getMaskedPhone())
  • com.collegebus.oop.model.CollegeBus
Concept 2
Inheritance

Hierarchical code reuse and specialized domain extensions using the extends keyword across two distinct class hierarchies.

  • AbstractVehicle → CollegeBus → AirConditionedBus
  • AbstractPerson → StudentPassenger / FacultyPassenger
  • Multi-level vehicle specialization
  • com.collegebus.oop.model.*
Concept 3
Polymorphism

Demonstrates both compile-time method overloading and runtime dynamic method dispatch (method overriding).

  • Overloading: calculateFare() with 1, 2, and 3 args
  • Overloading: allocateSeat() overloaded in manager
  • Overriding: Dynamic dispatch on calculateOperatingCostPerKm()
  • com.collegebus.oop.service.BusAllocationManager
Concept 4
Abstraction

Hiding intricate operational logic behind clean Abstract Classes and standard Java Interfaces.

  • AbstractVehicle & AbstractPerson base templates
  • Bookable: reserveSeat(), releaseSeat()
  • FareCalculable: fare calculation contracts
  • DatabaseOperations<T, ID>: generic CRUD contract
Concept 5
Packages

Clean separation of concerns organized into distinct namespaces preventing naming collisions and enforcing access scopes.

  • com.collegebus.oop.model: Encapsulated entities
  • com.collegebus.oop.interfaces: Pure contracts
  • com.collegebus.oop.dao: Direct JDBC data access
  • com.collegebus.oop.exception: Custom exceptions
Concept 6
Exception Handling

Hierarchical custom checked and runtime exceptions managed through structured try-catch-finally and resource management.

  • BusTransportationException: Base checked class
  • SeatNotAvailableException: Capacity violation
  • DuplicateBookingException: Quota violation
  • DatabaseOperationException: Wrapped SQL errors
DBMS Integration

Direct JDBC Connectivity & Relational Schema Design

ACID Transaction guarantees, parameterized PreparedStatements, and 13 normalized tables.

Relational Database Tables (InnoDB)
Table Name Primary Key Relationships / Foreign Keys
users user_id Parent for students, teachers, bookings
students student_id 1:1 with users(user_id) ON DELETE CASCADE
teachers teacher_id 1:1 with users(user_id) ON DELETE CASCADE
buses bus_id Parent for trips(bus_id)
drivers driver_id Assigned to trips(driver_id)
routes route_id Parent for route_stops, trips
bus_stops stop_id Master catalog of Chennai stops
route_stops route_stop_id Junction table (route_id + stop_id)
trips trip_id FK to buses, routes, drivers
bookings booking_id FK to trips, users, bus_stops
